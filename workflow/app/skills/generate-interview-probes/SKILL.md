# 面试问题生成方法论

## 激活条件
- 技术评估发现未验证声明后
- JD存在可通过面试弥补的缺口时
- 风险评估识别出需要人工判断的领域时
- 需要生成行为+技术问题集时

## 问题设计原则

### 1. 探查未验证声明 (优先级1)
对每个未验证的技术声明，生成问题：
- 从宽泛开始，逐步深入实现细节
- 问"为什么"和"考虑过哪些替代方案"
- 要求提供具体指标及基线
- 探查故障场景和调试方法

模板：
```
Level 1 (热身): "谈谈你在[技术]方面的经验"
Level 2 (深度): "在你的[具体项目]中，你是如何处理[具体挑战]的？"
Level 3 (压力): "如果[故障场景]，会发生什么？你会如何排查？"
Level 4 (架构): "如果今天重新设计，你会改变什么？为什么？"
```

### 2. 暴露简历缺口 (优先级2)
对JD中每个已识别的缺口：
- 设计给候选人展示相邻知识的机会的问题
- 包含测试可迁移技能的场景化问题
- 标注哪些缺口可培训 vs 硬性门槛

### 3. 行为校准 (优先级3)
基于职业轨迹和角色转换：
- 管理声明 → 领导力问题
- 跨团队声明 → 协作问题
- 架构声明 → 决策制定问题

## 输出格式
```json
{
  "probes": [
    {
      "category": "technical_depth|gap_verification|behavioral",
      "targetClaim": "被探查的具体简历陈述",
      "question": "面试问题",
      "difficulty": 1-4,
      "expectedSignals": ["好答案应包含的要素"],
      "redFlags": ["暗示编造或浅薄知识的信号"],
      "followUp": "初始答案模糊时的追问"
    }
  ],
  "interviewStrategy": "建议的问题排序和时间分配"
}
```

## 需避免的反模式
- 任何候选人都能从教科书回答的通用问题
- 测试记忆而非理解的问题
- 暗示预期答案的引导性问题
- 与具体岗位要求无关的问题
